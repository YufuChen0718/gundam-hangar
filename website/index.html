Gundam Hangar

An Interactive Gundam Customization and Animation System for Desktop Web and Apple Vision Pro

Team Members: Yufu Chen, Zihan Wang, Junxiang You, Dongyang Dai
Website: https://yufuchen0718.github.io/gundam-hangar/
Source: https://github.com/YufuChen0718/gundam-hangar

1. Summary

We propose Gundam Hangar, a web-based interactive 3D Gundam customization and keyframe animation system built desktop-first for modern browsers and adapted for windowed operation in Apple Vision Pro Safari. Starting from a hierarchical procedural rig and transitioning to a multi-region articulated GLB Gundam asset, we will implement our own modular socket attachment transforms, per-region material recoloring, quaternion keyframe interpolation with easing, and an animation state machine supporting smooth pose blending across interrupted actions. We will evaluate our system quantitatively through socket attachment error verification, joint-angle continuity curves comparing cut versus blended transitions, and median/95th-percentile frame-time benchmarks across desktop and Vision Pro Safari, while reserving native visionOS shell integration, immersive WebXR viewing, and drag-and-snap weapon assembly as aspirational extensions.

2. Problem Description & Technical Approach

Mecha models feature articulated joint hierarchies, distinct armor plating regions, and interchangeable equipment, making them an ideal testbed for interactive 3D graphics. However, transforming a static 3D Gundam asset into a responsive, customizable, and animated virtual hangar introduces several tightly coupled computer graphics challenges: external weapon assets often use inconsistent scales and coordinate conventions, attached equipment must remain rigidly aligned with moving limbs across arbitrary poses, discrete key poses must be interpolated into continuous motion without visual pops when users switch actions mid-animation, and the user interface must stay synchronized across desktop mouse controls and Apple Vision Pro gaze-and-pinch interactions.

Our project follows a desktop-first, Vision Pro (windowed Safari) second engineering route. Users inspect, recolor, equip, and animate a Gundam-inspired mobile suit inside a virtual hangar in a desktop browser, and open the exact same web application inside Apple Vision Pro Safari (windowed mode) backed by a unified state and command layer.

Key Graphics & Systems Challenges

  • Attachment Consistency: Computing and maintaining exact world-space position and orientation of interchangeable handheld weapons and back-mounted equipment across hierarchical joint motions.
  • Animation Continuity: Sampling keyframe poses with easing and spherical linear interpolation (slerp), and blending smoothly from any interrupted in-flight pose to a new target clip without angular discontinuities.
  • Cross-Device State & Input Consistency: Decoupling UI controls from direct scene-graph mutation via a shared command layer so desktop orbit/tab interactions and Vision Pro Safari gaze-and-pinch controls remain strictly synchronized.
  • Real-Time Performance: Balancing GLB triangle counts, cloned per-region PBR materials, and shadow rendering to sustain smooth frame rates on both desktop browsers and Vision Pro Safari.

2.1 Asset Preparation, Rig Abstraction, and Modular Attachments

To decouple graphics systems engineering from asset cleanup bottlenecks, we define a unified MechaRig interface exposing a top-level displayRoot (the sole node used for whole-model rotation and scaling), named program joints (torso, head, rightShoulder, rightElbow, rightWrist, leftShoulder, leftElbow, leftWrist), initial bind-pose rotations, named attachment sockets (rightHand, leftHand, back), and four isolated PBR material regions (primary, secondary, accent, frame). In Week 1, a procedural hierarchical box prototype (proceduralMecha.ts) implements MechaRig so animation, equipment, and UI modules can be developed and tested immediately. In Week 2, we standardize a full mecha asset and equipment models in Blender (+Y up, +Z forward, units in meters, isolated regional materials) and map its skeleton to MechaRig via rigConfig.ts and loadMecha.ts.

Each weapon (rifle, beam sword) and accessory (removable backpack) attaches to a target socket with an asset-specific calibration offset that aligns its grip center and forward axis (+Z). The equipment's world transformation matrix is given by the hierarchical chain:

M equipment world = M joint world ⋅ M socket joint ⋅ M equipment socket

2.2 Custom Keyframe Animation and Pose Transition Blending

Rather than relying on Three.js's built-in AnimationMixer, AnimationClip, or KeyframeTrack, we implement our own keyframe animation pipeline from scratch using only basic math primitives (Quaternion, Matrix4, Quaternion.slerp). We author keyframe clips (clips.ts) for three upper-body actions—idle, aiming a rifle, and swinging a beam sword—storing joint rotations relative to each joint's bind pose (applied as joint.quaternion = bindPose × offset).

At each frame, our pose sampler (samplePose.ts) locates the bounding keyframes, applies timing/easing curves, and interpolates joint orientations via quaternion slerp. Our playback state machine (animator.ts) manages looping, holding, mid-action interruption, and transition blending: when a user triggers a new action while another is playing, the animator captures a snapshot of the current pose and blends smoothly into the target clip over a configurable transition window, supporting both blend and abrupt cut modes for direct experimental comparison.

2.3 Shared Command Architecture and Vision Pro Adaptation

All user interactions flow through a strict unidirectional architecture: UI components invoke pure operations in commands.ts (setColorPreset, setRegionColor, equipWeapon, setBackpackVisible, playAction, setTransitionMode, rotateModel, resetModelTransform), which update a serializable JSON store (HangarState) and drive the rig, equipment manager, appearance controller, and animator within a single renderer.setAnimationLoop render loop.

The baseline desktop interface provides OrbitControls inspection alongside tabbed controls for Appearance, Equipment, Animation, and Debug diagnostics. For our baseline Apple Vision Pro milestone, the same web application runs in Vision Pro Safari (windowed mode) with gaze-and-pinch friendly target sizing and explicit on-screen rotation/zoom controls. Immersive spatial viewing via WebXR and a native visionOS WKWebView shell are structured as aspirational extensions atop the shared commands layer.

3. Goals and Deliverables

3.1 Planned (Baseline) vs. Aspirational Deliverables

To guarantee a reliable, well-tested system within four weeks, we draw a strict boundary between our required Baseline Deliverables (desktop web + windowed Vision Pro Safari) and our Aspirational Deliverables (native visionOS wrapper, immersive WebXR mode, and spatial drag-and-snap assembly). Immersive XR is explicitly not a baseline deliverable.

Planned Deliverables Baseline (Required)

  • Articulated Gundam Rig: Procedural box-prototype rig in Week 1 and full articulated GLB Gundam mobile suit in Week 2 implementing MechaRig.
  • Regional Appearance System: 3 curated color presets plus independent color pickers for 4 armor regions (primary, secondary, accent, frame).
  • Modular Equipment Sockets: 2 swappable handheld weapons (rifle, beam sword) and 1 removable backpack with calibrated socket offsets.
  • Custom Animation & Blending: 3 upper-body keyframe clips (idle, aim, sword swing) with mid-action interruption and smooth quaternion transition blending.
  • Desktop Web Hangar UI: Interactive camera orbit/zoom and Appearance, Equipment, Animation, and Debug tabs.
  • Vision Pro Safari (Windowed): Running the same web app inside Apple Vision Pro Safari with enlarged gaze/pinch targets, explicit rotate/zoom buttons, and device frame-time profiling.
  • Quantitative Evaluation Suite: Socket attachment error verification, joint-angle continuity CSV export/plots (cut vs. blend), and median/p95 frame-time diagnostics.

Stretch Extensions Aspirational (If Time Permits)

  • Native visionOS Shell: Packaging the web hangar inside a native visionOS application container using WKWebView.
  • WebXR Immersive Mode: Rendering the Gundam stereoscopically in space with floating spatial menus via Safari WebXR.
  • Drag-and-Snap Weapon Assembly: Interactive spatial manipulation where dragging a weapon within distance and angular thresholds of a compatible socket displays a preview and snaps it into place.
  • Explicitly Out of Scope: Full-body inverse kinematics (IK), walking locomotion, combat physics, complex multi-mode transformations, multiplayer networking, and real-world room reconstruction.
Planned End-to-End Demo Sequence:
Load Hangar Scene → Orbit & Zoom to Inspect Gundam → Switch Color Presets & Customize 4 Armor Regions → Equip Beam Sword → Play Sword Swing Animation → Swap to Rifle Mid-Action → Smoothly Blend into Aiming Pose (demonstrated on Desktop Browser and Windowed Vision Pro Safari).

3.2 Evaluation Metrics

Evaluation Dimension Quantitative / Qualitative Methodology Diagnostic Output
Attachment Correctness Across sampled keyframes of all three clips, compare the scene-graph world transform of attached weapons against an explicit matrix product MjointworldMsocketjointMequipmentsocket, and visually inspect grip alignment across poses. Position error (mm) & angular error (deg) check + multi-pose grip screenshots
Animation Continuity Trigger interactive action switches (e.g., swing → aim mid-swing) under both cut and blend transition modes and record per-frame joint angles and angular velocities. Joint-angle time-series CSV export and comparative continuity plots
Interaction Reliability Execute structured stress checklists combining rapid weapon swaps, regional recoloring, mid-clip interruptions, and camera/transform resets across desktop and Vision Pro Safari. Verification pass/fail matrix confirming zero orphaned meshes or desynchronized state
Rendering Performance Measure frame intervals over fixed benchmark runs (target ~60 FPS at 1920×1080 on desktop; windowed Safari characterization on Vision Pro), comparing procedural prototype vs. full GLB and shadows on vs. off. Median and 95th-percentile (p95) frame time (ms) charts across configurations

3.3 Questions We Plan to Answer

  1. Modular Socket Reusability: Can a shared hierarchical socket and offset transform system support multiple weapon and accessory combinations across all upper-body animations without re-authoring per-weapon clips?
  2. Transition Blending Quantitative Benefit: How much does snapshot-based quaternion pose blending reduce peak angular velocity spikes (pose discontinuities) compared to immediate action cuts during interactive switching?
  3. Cross-Device Rendering Trade-offs: How do model triangle complexity, per-region material cloning, and dynamic shadow maps impact median and p95 frame times on a desktop browser versus windowed Safari on Apple Vision Pro?

4.3 Risk Management

  • AI/External Model Rigging & Deformation Issues: Candidate GLB assets will be inspected in Blender during Week 1. If skeletal skinning causes severe armor warping, we will partition the mesh into rigid hierarchical sub-parts matching our MechaRig joint structure.
  • Asset Integration Delays: Because the Week 1 procedural box prototype implements the exact same MechaRig interface as the final GLB asset, animation, equipment, UI, and evaluation systems can be built and verified independently without blocking on 3D modeling.
  • Vision Pro Device Time & Platform Constraints: Making Vision Pro Safari (windowed mode) our baseline guarantees cross-device demonstration using standard web technologies, while keeping native visionOS WKWebView and immersive WebXR as zero-risk aspirational goals.
  • Scope Creep: We enforce a strict feature priority order: Socket Attachments > Animation Blending > Desktop UI > Vision Pro Windowed Safari > Aspirational Extensions.
